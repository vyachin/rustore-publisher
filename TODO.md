# rustore-publisher — план реализации 0.0.1

Репозиторий: `github.com/vyachin/rustore-publisher`. Команды: `doctor`, `status`,
`version`, `completion`, `publish`. Реализация приложения ещё не началась.

Подробный контракт перенесён в [docs/design.md](docs/design.md) — единственный
источник правил CLI/API/JSON/ошибок/Actions. Здесь остаются задачи и критерии
готовности; исторические ответы из чата не дублируют спецификацию.
Правила языка и разработки — в [AGENTS.md](AGENTS.md).

## Решения по последней проверке плана

- [x] Отложенная публикация (`delayed`, `--publish-at`, окно даты и запас 30 минут)
      перенесена в 0.0.2; в 0.0.1 остаются только `manual|instantly`.
- [x] AUTO_CHECK учитывать как отправленную версию; использовать sendDateForModer
      при skip и восстановлении после потерянного ответа.
- [x] Защититься от наследования partialValue: явные 100% для MANUAL/INSTANTLY,
      сверка созданной версии.
- [x] Установить общий timeout=30m в CLI/Action, 0 — явное отключение.
- [x] Описать JSON-поля, закрытые phase/outcome/error.code и нормализацию testingType.
- [x] Определить status без ID, сверку серверных полей, Z как UTC, GAME/GAMES,
      различение отсутствующего объекта и отказа доступа.

- [ ] При необходимости — ограниченное ожидание модерации или публикации после commit.
      Короткое ожидание готовности AAB до commit уже входит в 0.0.1.
- [ ] Исследовать выбор типа тестирования через `publish` по документированным
      методам и тестовому приложению. Новые команды требуют отдельного решения об объёме.

Сроки не предполагают немедленного одобрения модерации: интеграционная проверка
ручного выпуска зависит от внешнего процесса модерации. При подготовке этого
плана код приложения не реализовывался и операции записи в магазине не выполнялись.
